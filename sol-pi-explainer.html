1The thesis: optimize the harness, not the model

Most efficiency work targets the model — faster kernels, quantization, cheaper routing. SoL-Pi targets the harness: the code that presents state, exposes tools, and processes feedback. Harness changes require no model training and compose with every other efficiency win.

Lowers tokens used per task — the first-order cost for long-horizon, unattended agents.

⇄ The isolation boundary
Held-out results never feed back into search. The prototype enforces this with heldOutVerdict, which re-applies both acceptance gates to the held-out result and rejects the candidate on failure — a regression there is reported as a failure, not as a pass. This is what prevents search from patching task-specific solutions into the harness.

3The two sequential gates

Gate 1 — capability

Every capability metric must stay within its predeclared tolerance.

Metrics and tolerances are fixed before search begins and are kept outside the optimizing agent's control — it cannot game the acceptance criteria. Prototype: aggregateScore within 5% of baseline.

Gate 2 — efficiency

At least one declared efficiency metric must improve.

Among candidates passing both gates, only the nondominated set is retained. Prototype: tokenTraffic or cost must improve by ≥ 5%.

4The four retained mechanisms

Action Fusion action execution · tools

Base harness: an edit, then a separate command to test or build it — three API calls. Action Fusion adds an optional then_run parameter to file-mutation tools and returns both outcomes in one observation: 3 calls → 2. Commands that must inspect the mutation result stay separate.

saves 1 model round trip per edit prototype: 1 model-side fusion / run, 0% measured

Online Context Compact context management · progress

Reconsiders when to compact, at plan-step completion boundaries. At each boundary it estimates remaining requests from observed requests-per-step and unfinished steps, caps that by what would fill the context window, then compares projected input savings against the cache-rewrite cost. Compaction only fires when the gate passes, or when usage approaches the window limit. Later compactions require a larger margin to cover unrecovered rewrite costs.

paper: cache-read 2.13B → 1.06B tokens prototype: −34.0% traffic

ObservationPack observation storage · context

Large tool outputs (> 10 KiB) recur in later requests long after they stop mattering. ObservationPack archives them locally, sends the full result for the next two requests, then substitutes a stable handle, the original size, and a short excerpt of complete head and tail lines. A recall_observation tool serves the exact original (or a 4 KiB page of it) by handle, so the instruction to recall is an affordance the agent can act on.

prototype: 15 archived, 14 substitutions −97.7% cost on long-horizon

Evidence-Preserving Reducer delegated reading · context

Compresses build/test logs (≥ 4 KiB) using a low-cost model, then verifies the receipt deterministically — schema, source hash, exit status, exact quotes, and size. Any failure, suspected credential, or no size reduction falls back to the original log. Runs before ObservationPack projects the context, which skips verified receipts to preserve evidence. The auxiliary model extracts; the main agent still diagnoses and acts.

deterministic verifier, 5 checks prototype: 15 logs reduced, 1.12 MB saved

Same shape as the paper's results: score is preserved at 1.000 across every harness while cost drops sharply, and savings concentrate in the large-object mechanisms. Here the Evidence-Preserving Reducer dominates — once it matches the log formats the environment actually emits, it compresses 15 logs and saves 1.12 MB on the long-horizon task alone. Three honest caveats: Action Fusion measures ~0% because this corpus's scripted policy already batches the write and the run in one turn, leaving no round trip to eliminate (an earlier run reported −23.6% for it, but that was missing work, not saved work). The substituting mechanisms are smaller than they look for a reason: these figures bill the prefix cache, so a request pays the read price for the part that repeats the previous request, the write price for the appended tail, and the full input price for anything a mechanism rewrote mid-context. ObservationPack substitutes archived observations in place, invalidating the suffix that was already cached — its saving drops from 79.5% to 52.2% once that rewrite is billed, and OnlineContextCompact's from 33.7% to 12.3%. The Reducer escapes the effect because it compresses the log before it reaches the context. And single-mechanism effects differ from the paper because this corpus is 6 environments with a scripted backend; the paper's stack-level interaction is what its Fig. 7 analyzes.

6Cross-model transfer

SoL-Pi was developed on GPT-5.6 Sol and applied to Opus 5 without further search or adaptation. It retained 94.3% of Pi's score while cutting traffic 44.7% and cost 33.5%. Mechanisms trigger less often on the unseen backend, but still improve efficiency where they do — evidence that the improvements live in the harness, not in backend-specific tuning.

Why this matters: the mechanism code did not change between backends. If the gains had come from overfitting to one model's trajectory patterns, transfer would have collapsed. The paper's Fig. 6 shows lower trigger rates on Opus 5 with efficiency still improving.
What this prototype does not show: it runs a single scripted backend standing in for GPT-5.6 Sol, so it reproduces none of the cross-backend evidence above. The transfer result belongs to the paper; this prototype measures harness-layer effects with the model held constant, which is a different claim. Building a genuine second backend — one whose policy actually differs, not just its id — would be required to say anything about transfer here.

7The recursion, and its limits

Recursive efficient improvement

A cheaper harness lowers the cost of the auto-research that builds its successor: a fixed budget covers more environments, trajectories, and ideas. Efficiency becomes both an outcome of harness research and an input to expanding it. The authors are explicit that this is a long-term vision, not an effect the study demonstrates.

Pretraining the harness

Exposing the harness to many tasks and updating it from the resulting trajectories is analogous to pretraining. The hypothesis: scaling executable environments and idea diversity yields sustained, transferable gains — moving automated harness discovery toward production-level outcomes.

What the paper does not claim: no scaling law for search breadth/depth (search is too expensive to ablate under a fixed budget); single-backend training only; and held-out evaluation is on the public 51/134 EdgeBench tasks. The authors call the transfer evidence preliminary.
